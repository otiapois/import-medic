# Subsystem: Web Workbench & Static SEO Landing Pages (`src/web/`)

## Browser Workbench

- [`App`](../../src/web/App.tsx) renders the route heading and selects a workbench. In the single-file [`Workbench`](../../src/web/Workbench.tsx), visitors can select Shopify Products, QuickBooks Bank, Stripe / PayPal, **Xero Bank CSV**, or **FreshBooks CSV** and add a local file. Xero includes **Load Synthetic Xero Balance Break Demo** for a known held example.
- Single-file repair and **Build Update** pass local File objects and settings to a [Vite-bundled Web Worker](../../src/core/worker/diff.worker.ts), where parsing, repair, comparison, and export take place. The UI keeps the selected File objects and settings so Cancel can terminate processing and Resume can rerun the current job. Clearing or replacing a file discards its current results. QuickBooks exposes layout, date order, and Credit / Debit convention. Stripe / PayPal exposes export format, date order, the PayPal Memo filter, and **Fee convention** for generic accounting sheets. Native provider headers determine the convention when present.
- [`Results`](../../src/web/workbench/Results.tsx) shows counts, encoding, and line endings. It requests only the active page of issues, changed cells, or removed rows. The Before / After Table loads when selected. Review actions and processing phases announce updates to assistive technology.
- [`ExportActions`](../../src/web/workbench/downloads.tsx) requests CSV and JSON or text audit bytes on demand, warns when a repair has unresolved issues, and disables unsafe exports. The formula guard escapes formula-like text while preserving valid signed decimals. It is always on for Xero and available as an option for the other profiles. The export panel shows the exact count of guarded cells. The inquiry card provides a downloadable blank brief and displays that quote requests are closed.
- Single-file repair separates automatically fixed issues from manual edits, keeps source line numbers visible as wide diff panels scroll, and offers a platform suggestion based on the uploaded headers for the user to confirm.
- For held Stripe or PayPal exports, the review shows the original Gross, Fee, and Net with the expected Net and the fee convention. For mixed currencies in a bank projection or a FreshBooks expense file, it shows per-currency counts and expandable physical source lines. The same evidence is available in the Bookkeeper Sign-Off report.
- **Tax Reconciliation (Net + Tax == Gross)** and **Duplicate Transaction Alerts** appear in **Issues & Review** when applicable. Tax discrepancies and exact duplicate matches retain their original physical line evidence in the workbench, JSON audit, and offline Bookkeeper Sign-Off, including on held repairs. [Accounting checks](csv-engine.md#tax-and-duplicate-transaction-checks)
- Xero and FreshBooks expose **Date format** for the source file. **Running-Balance Chain Audit** appears for bank results with a balance column. The card shows the link status and, when known, opening balance, net movement, and closing balance. A break carries the line number, expected balance, actual balance, and signed discrepancy. For an unverifiable chain the card gives the source reasons. Xero results without a source balance show **Balance chain unavailable**. [Running-balance contract](csv-engine.md#running-balance-chain)
- **Download Bookkeeper Sign-Off (.html)** appears with the single-file export actions for a current completed repair. The worker prepares the printable local report on demand. It can document unresolved lines when the repaired CSV is held. [Bookkeeper report contract](csv-engine.md#offline-bookkeeper-sign-off)
- **Auto-Categorize Rules** opens on the home route. Choose a transaction CSV, reuse a verified current accounting source with its rows intact, or load the synthetic demo. Add, edit, and reorder rules and load or save a rule pack. Review coverage, exception lines, and the account summary before downloading a ready pack. A hold leaves the categorization audit available. [Categorization workflow and input contract](categorization.md)
- **Payout vs Bank Reconciler** opens in the home route's **Accounting workflow** switch. Choose two local CSVs or load the synthetic Shopify month-end demo. Confirm the actual currency of any file without a Currency header, then choose the inclusive settlement lag in calendar days. Review the proven pairs, exceptions and separate currency totals. Download the two review CSVs, audit, and branded offline sign-off. [Payout input and output contract](payout-reconciliation.md)
- Price Update Studio opens in Shopify mode on the existing route. **WooCommerce** and **BigCommerce** each accept their native baseline or load a labeled synthetic demo. The workbench compares one native baseline with one to three supplier CSV or XLSX files. Use **+ Add another supplier sheet** and check each file's label, row count, worksheet, and mapping. The supplier order determines first and last in **Supplier conflict policy**. Conflicts show the candidate sources, raw values, and original source rows. Confirm a preference for the current batch and review the selected source in the diff.
- A supplier workbook with multiple visible tabs shows a **Supplier worksheet** selector beside its filename. The initial choice is the first visible tab. For each slot, choosing another tab refreshes its headers and suggested mapping for confirmation. The exact selected name stays with that slot.
- In Shopify mode, a baseline with `Price / <Market>` columns adds **Target price list** above column confirmation. Start in **Base store (Variant Price)** or select one exact market header. For market runs, confirm any manual FX conversion into the target market currency. Review the selected scope in the diff, audit, and Client Sign-Off HTML. The Markets export leaves inventory out of both files. [Shopify Markets contract](shopify-price-diff.md#shopify-markets-price-scope)
- **Build Update** opens by default at `/shopify-price-update-diff`. **Verify Update / Rollback CSV** on the same page accepts the original platform export and one candidate CSV, then shows the safety verdict, fingerprints, and exact changed cells. **Load last generated pair** supplies the original baseline and both native files from the current comparison. **Check a rollback with its matching update** adds the corresponding update as a third file for a saved pair. The inspector can replay that update before testing the rollback. [Standalone inspector contract](shopify-price-diff.md#verify-before-import)
- **Catalog & Barcode Hygiene** opens within **Verify Update / Rollback CSV** on the same route. Choose a platform for each catalog, add the primary CSV and an optional secondary CSV, or load the synthetic GS1 and duplicate SKU demo. Review the row and finding counts and filter issues by category. Completed runs offer the diagnostic CSV, audit JSON, and branded offline report. Ready runs also offer a cleaned CSV and exact original rollback per source. [Catalog hygiene contract](catalog-hygiene.md)
- Below the supplier inputs, **Bundle BOM sheet (optional)** accepts a local CSV or XLSX. **Load Synthetic Kit BOM Demo** loads a synthetic baseline, supplier cost sheet, and nested BOM. After comparison, **Bundle Cost Rollup** shows kit costs and margins with component sources or the blocking source diagnostics. Adding, replacing, or removing the sheet invalidates the previous result and its downloads. [Bundle BOM contract](shopify-price-diff.md#bundle-and-kit-cost-rollup)
- **Sale Campaign Pack** is the third mode on the same route. Its default **Retail Promo Pack** workflow accepts one catalog CSV, previews the scoped discount and exact revert values, and allows rows to be skipped or restored. A blocking price or identity problem holds the native pair. The verified launch and revert downloads share SHA-256 fingerprints with the JSON audit and offline Campaign Sign-Off HTML. The pair can be opened in the existing inspector. [Sale Campaign Pack contract](promo-campaign.md)
- **Wholesale B2B Line-Sheet** uses the workflow switch inside **Sale Campaign Pack**. Open **Load Synthetic 3-Tier Wholesale Demo** or choose one catalog CSV and an optional cost and MAP sheet. Review the calculated tiers in **Internal margin review**, switch to **Buyer-safe preview**, then download the available files. A pricing hold leaves the audit and its source evidence available. The selected-tier Shopify catalog CSV has its own existing-catalog title and tier selection. [Wholesale pricing and file contract](wholesale-pricelist.md)
- **Supplier Delta** is the fourth mode on the same route. Its **2-Sheet Delta** view uses a local worker to compare a previous and a new supplier CSV or XLSX, with independent worksheet and column choices, a synthetic demo, category filters, and available SHA-256 fingerprints. Changing a source, worksheet, or mapping clears the previous comparison. A blocking source or mapping issue holds the delta CSV and offline HTML. The audit remains available for review. [Supplier Delta contract](supplier-delta.md)
- **Multi-Period Cost Creep (2–6 sheets)** opens in **Supplier Delta**. Add chronological period slots or choose **Load Synthetic 4-Quarter Cost-Creep Demo**. Check period labels, worksheets, and mappings, set the cumulative creep threshold, and optionally add a store retail CSV. The panel summarizes hikes and SKU lifecycle with inline SVG trends and filters. Ready runs make **Cost-Creep CSV**, **Audit JSON**, and **Vendor Negotiation Brief (.html)** available. A completed hold keeps the audit for review. [Cost-creep contract](cost-creep.md)
- **Migrate Catalog** uses the same route. Select different **Source platform** and **Target platform** values, then choose one catalog CSV or **Load Synthetic Multi-Variant Demo**. Review **Field Mapping & Unmapped Disclosure**, the **Target catalog preview**, and **Migration file custody**. A blocked conversion holds **Target Import CSV** and keeps **Migration Audit JSON** and **Migration Sign-Off (.html)** available for review. [Catalog migration contract](catalog-migrator.md)
- **Inventory Sync > Inventory Update** uses the same route. Choose a Shopify **All states** inventory export and up to three supplier stock sheets, or select **Load Synthetic Multi-Location Demo**. Select **Target Location**, map the supplier SKU and quantity columns, and review the projected on-hand change and buffer withheld. **Inventory Update CSV** and **Inventory Rollback CSV** are available for a ready run with changes. **Inventory Audit JSON** and **Inventory Sign-Off (.html)** also report completed holds. [Inventory Sync contract](inventory-sync.md)
- **Inventory Sync > Reorder PO Pack** uses the **Inventory workflow** switch in the same tab. Choose **Load Synthetic Multi-Supplier PO Demo** or add the inventory CSV and up to three supplier catalogs. Select the location and each XLSX worksheet, review the defaults and supplier policy, then check the SKU count, units, suppliers, spend, and **Supplier breakdown**. Ready orders offer supplier CSVs, a consolidated summary CSV, a PO audit JSON, and the branded offline PO pack. A hold keeps the audit for review. [Reorder PO Pack contract](purchase-order.md)
- **Inventory Sync > Landed Cost Calculator** opens on the existing price workbench route. Choose an invoice CSV or XLSX, select a visible worksheet if needed, or use **Load Synthetic Container Import Demo**. Enter the currencies, charges, allocation method, and duty estimate basis. Confirm a manual FX rate when the currencies differ. Review the exact cent totals, per-SKU cost and uplift, then download the available files. A held batch retains the audit and withholds the CSV and branded offline sheet. [Invoice and cost handoff](landed-cost.md)
- Open **Shortcuts (?)** from the page or press `?` outside text entry. The dialog documents `/` for available search and `Escape` to close or cancel with focus restoration. The dialog's setting disables single-character shortcuts.
- The queue pages in the worker and searches SKU or Shopify handle. Press `/` outside text entry to focus search. **Pricing formula & rounding** previews retail rounding, minimum retail, and the proposed prices for **Tiered cost brackets**. Its optional manual FX controls accept source and destination currency codes and an exact rate. Shopify can calculate compare-at pricing automatically when that column is unmapped. Changes to columns or pricing require confirmation.
- **Batch Impact & Margin Summary** shows price movement and, where available, gross margins and stock impact across catalog platforms. **Zero / Negative Margin Alert** filters the paged diff while retaining the search term. [Catalog impact contract](shopify-price-diff.md#catalog-impact-and-margin)
- **Interactive Margin What-If** starts collapsed in **Build Update**. Open it to compare the current rule and selected presets or custom markup and FX scenarios in the local worker. Custom inputs accept `−99.99%` to `+100%` at up to two decimal places. The comparison shows up to six scenarios including the current rule. **Apply Scenario** reruns the batch using an eligible result. [Scenario calculations and export contract](shopify-price-diff.md#margin-what-if-simulator)
- Formula review shows **Supplier raw**, **Computed price**, the matched tier when applicable, and the effective **After** amount. The visible **Change** value uses a sign and up to two decimal places, such as `+13.04%` and `-10%`. The calculations and six-decimal audit representation retain their precision. The desktop **Review** column remains usable with both supplier source and quantity columns visible. Review supports row edits and skips. The price editor accepts final store-currency amounts. Pressing `Escape` cancels an active edit and returns focus to its triggering row button.
- **Inventory qty column (optional)** defaults to **Leave unchanged**. Mapping a quantity column enables before-and-after quantity review in the diff. Invalid quantities need an override or skip. A valid large drop or zero-out can also be confirmed. The native pair remains held while blocking rows need review.
- Supplier recipes save the confirmed column names, thresholds, and formula guard setting to a local JSON file. Version 6 saves an explicit worksheet selection by exact name. Versions 1–5 still load, including their saved pricing, FX, inventory, conflict, and tier settings where applicable. Check the new batch's headers and worksheet, remap any mismatch, and confirm the current columns and any carried preference. Confirm store currency when prompted. A loaded FX recipe requires rechecking and reconfirming the rate before the new batch can export.
- A v1 workspace profile JSON carries `storeName`, `platform`, and `storeCurrency`, plus optional `dropThresholdPercent`, `increaseThresholdPercent`, `inventoryDropThresholdPercent`, and tiered `pricingRule`. It saves these defaults from the first supplier, including tier rounding and the floor. Select the matching platform before loading a profile to seed manual mappings. An explicitly loaded supplier recipe takes precedence and carries any saved FX or automatic compare-at settings and worksheet or column mappings. Settings live in memory until exported.
- The Shopify export offers **Download Safe Shopify Update CSV** and **Download Shopify Rollback CSV** once both native files pass local replay against the uploaded baseline. Both preserve required identity fields and complete affected product groups. The base-store pair includes a quantity field when mapped. If the opt-in formula guard finds an outgoing field that would need escaping, the native pair is blocked and the guarded audit remains available. The export panel shows how many cells would need protection.
- WooCommerce mode offers a native update and rollback scoped to existing product and variation identities, with optional sale price and stock. Both files must pass local replay against the uploaded baseline before download. [WooCommerce comparison contract](woocommerce-price-diff.md)
- BigCommerce mode accepts the legacy Bulk Edit product export and offers **Download Safe BigCommerce Update CSV** and **Download BigCommerce Rollback CSV** after local verification. The pair is scoped to supported product prices and tracked stock. The inspector also accepts BigCommerce native candidates. [BigCommerce comparison contract](bigcommerce-price-diff.md)
- **Amazon Seller Central** uses a Price & Quantity baseline and one proposal file, with **Load Synthetic Amazon Demo** available in **Build Update**. It shows min/max price findings on the original lines. The update and rollback preserve the baseline delimiter. The existing **Verify Update / Rollback CSV** tab can inspect the pair, including via **Load last generated pair**. Both workflows stay on `/shopify-price-update-diff`. [Amazon comparison contract](amazon-price-diff.md)
- **Download Client Sign-Off (.html)** is available with the diff audits after comparison. It prepares a standalone offline review with batch impact, supplier provenance, and matched tiers for store owners to review before a manual import.
- The **SHA-256 file fingerprints** section displays Baseline, supplier files, the optional BOM, and the available Update CSV and Rollback CSV on `/shopify-price-update-diff`. On the home single-file workbench it displays Source CSV and the available Repaired CSV. Each fingerprint has a copy control. If clipboard access fails, the control selects the text for manual copying. The values come from the current completed worker run and match its JSON audit and sign-off footer.
- Uploaded files, diagnostics, edits, and reports stay in memory until the browser creates a local download. The workbenches use same-origin static code assets and keep user data in the browser without persistent storage.

## Local CLI Command

The single-file repair and six Price Update Studio modes each offer a collapsed **Local CLI Command** disclosure after the existing workflow controls. Open it to read or copy a command for a local ImportMedic checkout. Use the npm bundled with a supported Node.js release. Replace example filenames with local paths and choose a fresh output directory. Clipboard denial selects the read-only command for manual copying. The helper keeps uploaded paths and file bytes out of the command. Worksheet names and other exact text settings use UTF-8 base64url flags where needed. A long command can exceed the Windows npm launcher's limit, including after longer local paths are substituted.

In **Build Update**, confirm the applicable mappings, then save a current **Supplier Recipe (.json)** for each supplier in the displayed order. Use these files with the placeholder recipe arguments. The helper carries the current market, applicable confirmations, and row review decisions. For an XLSX bundle BOM, save its worksheet to CSV and select the CSV before copying a command. In single-file repair, apply browser cell corrections to a local copy before replay. Commands use default CLI report branding.

The **Inventory Sync** command carries per-sheet mapping, target location, and reserve settings. Review large drops for the local batch before adding `--approve-large-drop`. [Inventory CLI options](cli-automation.md#inventory-sync)

## Agency Sign-Off Branding

**Agency Sign-Off Branding** appears under **Workspace profile** in the price workbench, next to Bookkeeper export in single-file repair, and in the payout reconciler. The price workbench carries one in-memory brand across the Client, Campaign, Supplier Delta, Migration, Inventory, and Catalog Hygiene reports, the Vendor Negotiation Brief, the printable PO pack, the wholesale buyer line sheet, and the Landed-Cost Sheet. The Bookkeeper and payout branding controls can edit their own brand or restore it from a downloaded Workspace Profile JSON. Loading a profile there uses its branding and leaves the current source and processing settings in place. Use the JSON to carry branding across page navigation or sessions.

The v1 Workspace Profile accepts the optional `branding` object with `agencyName`, `preparedFor`, `contactNote`, and `accentKey`. Existing profiles without `branding` still load. Agency and client names are limited to 120 characters, and the contact note to 240. The agency name must be nonblank. Omit the client name or note in the report by leaving the corresponding field empty. The shared branding renderer escapes the supplied text in the report header and selects colors from `forest`, `navy`, `slate`, and `burgundy`. Contact notes render as plain text. Branded reports retain their offline content security policy and CSV fingerprints. The Supplier Delta, Cost Creep, Migration, PO, categorization, Catalog Hygiene, and payout reconciliation audits include the digest of the HTML with the current branding. [Shared branding renderer](../../src/core/branding/signoff-brand.ts)

[`routes.ts`](../../src/web/seo/routes.ts) matches the eight error slugs to their platforms and reads examples and FAQs from the bundled [error catalog](../error-catalog.json). Error pages show their catalog entry, platform pages show entries for their platform, and the home page shows one example per platform. The Shopify price update page has its own synthetic price comparison and FAQs. Reference links open the cited documentation when clicked.

`npm run build` bundles the browser entry with Vite. Then [`scripts/prerender.mjs`](../../scripts/prerender.mjs) builds and imports the Node-only [`entry-server.tsx`](../../src/web/entry-server.tsx) from `.vite/prerender/`. The script writes `dist/index.html` and a directory `index.html` for each non-root route. Each document includes a unique title, description, canonical URL, H1, the preselected workbench, before and after examples, FAQs, and `FAQPage` and `SoftwareApplication` JSON-LD. Build checks confirm catalog rule IDs against the core engine, enforce the 13 routes and M1 slug contract, and verify the emitted metadata, examples, FAQ content, and structured data.

[`main.tsx`](../../src/web/main.tsx) uses `createRoot` during Vite development and `hydrateRoot` on production documents using the route recorded in the HTML. The browser bundles the catalog and requires no runtime catalog request. Serve `dist/` at the root of a static host that resolves directory `index.html` for direct requests with or without a trailing slash. `npm run preview` serves both URL forms for the local production build.

Set `SITE_URL` to the approved HTTP(S) origin before building for a real host. The default `https://importmedic.example` is reserved for local handoff. The origin controls canonicals, structured-data URLs, `dist/sitemap.xml`, and the sitemap entry in `dist/robots.txt`.

[`LAUNCH_ROUTES`](../../src/web/seo/routes.ts) limits the initial indexing list to one through five known paths. The current list is `/` and `/shopify-price-update-diff`. Only these appear in the sitemap. The other pages serve `noindex,follow`, and `robots.txt` allows crawlers to read those directives.

Cloudflare Pages reads [`public/_headers`](../../public/_headers) from `dist/_headers`. The wildcard rule applies same-origin asset restrictions, blocks script connections and form submission, disallows framing, and sets `nosniff` and `no-referrer`. Vite production preview applies the same built rules to its responses. [Cloudflare Pages headers](https://developers.cloudflare.com/pages/configuration/headers/)

## Verification Commands

- `npm run build` renders and checks 13 routes, writes `sitemap.xml` and `robots.txt`, and copies response headers and license notices into `dist/`.
- `npm run test:e2e` runs against production preview with installed Edge. It checks real upload and download, keyboard focus, contrast, console errors, layout, requests, and static page identity on desktop `1440x900` and mobile `390x844`. The test compares the page width to the configured viewport. Wide diff tables scroll inside their preview panels.
