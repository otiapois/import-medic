# BigCommerce supplier price and stock diff

Use the legacy BigCommerce Bulk Edit product CSV and one to three supplier CSV or XLSX files. Match by exact SKU text, including leading zeros. The export may use `Product Code/SKU` or `Product SKU` as its single SKU heading. Both native files retain that heading. The comparison holds case-insensitive SKU collisions and unstable keys such as scientific-notation cells. For legacy variants, the Product and SKU rows preserve their original IDs, sequence, and option expression as exported. [Shared pricing and supplier comparison](shopify-price-diff.md) · [Legacy BigCommerce product updates](https://support.bigcommerce.com/s/article/Updating-via-Import?language=en_US) · [Legacy export field names](https://support.bigcommerce.com/s/article/Legacy-to-Modern-Product-Transfer?language=en_US)

## Native pair

The baseline requires `Price`, `Item Type`, `Product ID`, `Product Name`, and the SKU column. The writable columns are `Price` and optionally `Sale Price` on standalone `Product` rows and stock on eligible `Product` or `SKU` rows. Use the exported `Stock Level` or `Current Stock Level` column. Stock updates require a nonnegative whole quantity in the baseline and `Track Inventory` on the owning Product set to `by product` for a Product write or `by option` for a SKU write. The pair omits tracking settings, descriptions, categories, images, and metadata.

BigCommerce's legacy format displays `Price` on SKU rows as a reference field and does not accept variant sale pricing there. Grouped parent pricing is held because changes can affect inheriting variants. Rule rows and the modern importer use different formats and are outside this workflow. [Legacy BigCommerce product updates](https://support.bigcommerce.com/s/article/Updating-via-Import?language=en_US) · [Modern BigCommerce importer](https://support.bigcommerce.com/s/article/Modern-Import-Export-Overview?language=en_US)

Changed native fields need a known original numeric value for rollback. A price reduction requires `Sale Price` in the baseline so the workbench can check any existing sale. Original and final sale prices must be below their corresponding regular prices. The comparison treats a blank writable cell as no write under the legacy importer's **Ignore blank values during import** setting. It holds blank-to-value changes that would require clearing the value on rollback. The rollback retains the exact original text for supported changed fields. Confirm legacy mapping and **Ignore blank values during import** in the destination store. Keep category and other metadata mappings excluded. If the importer requires an additional category assignment, pause and review the mapping before proceeding. [Legacy BigCommerce product updates](https://support.bigcommerce.com/s/article/Updating-via-Import?language=en_US)

## Local verification and import

The browser re-parses the actual update and rollback bytes and checks the scoped writes and full snapshot recovery. Use **Verify Update / Rollback CSV** on the original baseline and a candidate to check allowed headers and identity, the exact price and stock differences, and both file fingerprints. With the matched update available, the inspector also verifies the rollback after applying that update. The audits and offline Client Sign-Off HTML carry the local review evidence. SHA-256 fingerprints identify the exact supplied and downloadable files. [Shared audit and fingerprint contract](shopify-price-diff.md#native-csv-pair-and-audit) · [Standalone inspector contract](shopify-price-diff.md#verify-before-import)

Review the exact identities, relationships, tracked stock, and current prices in the same store before a manual import. For a rollback, check for later price edits or stock movement and compare the current catalog to the matched update. The verification result applies to the uploaded baseline and files.
